# MediChain Verify (Ethereum Sepolia)

Pharmaceutical traceability and counterfeit-drug detection on the Ethereum **Sepolia testnet**.
A Solidity smart contract records medicine batches, custody transfers, verification scans and recalls.
An Express backend talks to the contract with `ethers`, and a React dashboard sits on top.

```
React dashboard  ->  Express API (ethers v6)  ->  MediChain.sol on Sepolia
```

## How it works
- `contracts/MediChain.sol` - the smart contract (port of the old Hyperledger Fabric chaincode).
- The secret verification code is **never stored on-chain**. The backend stores `HMAC(CODE_PEPPER, medicineId + code)` so a public chain can't leak or brute-force it.
- Only the backend wallet (the contract *operator*) can write; anyone can read the contract on Etherscan.
- REST API is unchanged from the Fabric version (`/api/medicines`, `/verify`, `/transfer`, `/recall`, histories, `/api/health`).

## Counterfeit reporting
The current custodian can file a counterfeit report from a medicine's detail panel. The batch is flagged
`SUSPECTED_COUNTERFEIT`, a red/orange **Counterfeit Alerts** panel appears on the registry for the manufacturer,
and **Review & Recall** opens the recall form pre-filled with the report. Recalling marks all reports resolved.
API: `POST /api/medicines/:id/report-counterfeit` with `reportedBy`, `location`, `details`.
Note: this feature changed the contract, so redeploy it in Remix and update `CONTRACT_ADDRESS` in Render.

## Deploy with no local software (browser only)

**1. Wallet + test ETH.** Install MetaMask, create a **new throwaway account** (never reuse a real one), switch to the Sepolia network, and get free Sepolia ETH from a faucet (Google Cloud Web3 faucet, Alchemy faucet, or the PoW faucet).

**2. Deploy the contract with Remix.** Open https://remix.ethereum.org, create `MediChain.sol`, paste `contracts/MediChain.sol`, compile with Solidity 0.8.20+ (enable optimizer, 200 runs), then in *Deploy & Run* choose **Injected Provider - MetaMask**, deploy, and copy the contract address. The deploying account becomes the operator.

**3. Get the operator private key.** MetaMask -> account menu -> Account details -> Show private key (throwaway account only).

**4. Host on Render.** Push this repo to GitHub, then on https://render.com choose New -> Blueprint and select the repo (it reads `render.yaml`). Set the secrets when asked:

| Variable | Value |
| --- | --- |
| `CONTRACT_ADDRESS` | address from step 2 |
| `PRIVATE_KEY` | throwaway operator key from step 3 |
| `CODE_PEPPER` | auto-generated by the blueprint - do not change it later |
| `RPC_URL` | defaults to a free public Sepolia RPC |

Render builds the frontend and serves it from the same service, so there is nothing else to wire up. Open `https://<your-service>.onrender.com/` and check `/api/health`; it should show `"status":"UP"`. The free plan sleeps after inactivity, so the first request can take up to a minute.

## Run locally (optional)
```bash
cp backend/.env.example backend/.env   # fill in the values
npm --prefix backend install && npm --prefix frontend install
npm run dev                            # API on :3000, UI on :5173
```

## Notes
- Each write waits for Sepolia confirmation (about 12-30 s). The UI timeout is set to match.
- Changing `CODE_PEPPER` after registering medicines makes their codes unverifiable.
- This is a testnet demo. A production system would add per-organization access control and key management.
